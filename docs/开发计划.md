# 多语言学习工具开发计划

- 制定日期：2026-10-15
- 状态：规划阶段，尚未开始实现。
- 产品方向：移动端优先，Web 端也能完成学习。
- 技术路线：React Native + Expo + TypeScript。
- 首发平台：Android + Web；后续单独验证和适配 iOS。

## 1. 产品目标

建立“学一课 → 做练习 → 保存进度 → 复习薄弱内容”的学习闭环，再扩展语言和高级能力。

第一版聚焦文字与发音、词汇、句子、语法、场景、听读练习和复习。AI 实时对话、精细发音、重音、弱读、语调评测放到后期升级。

移动端是主要入口。Web 端能够使用同一套课程、完成练习和保存本机进度。跨设备同步单独规划，不因支持两端而自动具备。

## 2. 首版范围

### 默认假设（课程制作前确认）

- 用户母语：简体中文。
- 首个目标语言：英语。
- 学习人群：入门和基础日常交流学习者。
- 无账号也可使用，课程和进度优先保存在本机。
- 先制作 10 节示范课程，每节围绕明确的学习目标。
- 先验证多语言架构，不承诺首版提供大部分语言的课程。

### 首版包含

- 语言与学习偏好设置。
- 课程目录、单课学习、词汇和例句。
- 发音示范与音频播放。
- 选择、填空、句子排序、听音选择。
- 答题解释、学习进度、错题记录。
- 间隔复习、每日复习队列。
- 已缓存课程离线学习，学习数据导出与恢复。

### 后期升级

- 登录、云备份、跨设备同步。
- 更多语言及不同母语的教学解释。
- 录音、自听与示范对比。
- AI 场景对话、语法和自然度反馈。
- 按语言开放精细发音、重音、语调评测。
- iOS 真机适配与分发。
- 内容管理后台、社区与付费功能。

## 3. 课程结构

采用“通用课程结构 + 语言专属规则”，不把英语语法作为所有语言的模板。

| 模块 | 内容 | 首版形式 |
| --- | --- | --- |
| 文字与发音 | 文字系统、拼读、发音、必要的转写或音标 | 讲解、示范音频、辨音 |
| 词汇与构词 | 高频词、词性、搭配、适用的词形变化 | 词卡、例句、练习 |
| 句子与语法 | 语序、疑问、否定、基础规则 | 句型讲解、填空、排序 |
| 场景应用 | 自我介绍、吃饭、购物、问路 | 短对话与场景练习 |
| 听读练习 | 听懂短句、阅读简短内容 | 音频、短文、理解题 |
| 文化与语用 | 礼貌、称呼、正式程度 | 穿插在课程中 |
| 复习 | 已学知识点与薄弱内容 | 到期队列与复习练习 |

单课流程：学习目标 → 新词与短句 → 音频及讲解 → 场景例子 → 练习 → 反馈 → 加入复习。

首版不对自由口语和自由写作给出能力评分。没有音频评测依据时，不显示“发音正确”。

## 4. 页面与体验

主要入口：

- 首页：继续学习、今日复习、最近进度。
- 课程：单元、课时、目标、完成状态。
- 复习：待复习内容、作答、复习结果。
- 我的：语言偏好、统计、离线内容、备份与设置。

核心页面：首次设置、课程详情、课时学习、练习反馈、课后结果、复习、进度、数据导入导出。

体验要求：

- 手机支持安全区域、系统返回、单手操作、软键盘避让。
- Web 适配宽窄屏和键盘；排序题不能仅依赖拖拽。
- 音频支持播放、暂停、重播，以及加载失败重试。
- 答错解释原因，区分尝试次数与最终结果。
- 界面文案和课程内容分开管理。
- 正确显示非拉丁文字、组合字符、长文本和从右向左文字。

## 5. 技术方案

| 领域 | 初始方案 | 说明 |
| --- | --- | --- |
| 客户端 | Expo + React Native + TypeScript | Android 与 Web 共用主要逻辑 |
| 导航 | Expo Router | 按平台适配导航体验 |
| 状态 | Zustand，按需引入 | 持久化记录不能只放内存 |
| 内容 | 带版本 JSON + 运行时校验 | 初期不依赖课程后台 |
| 存储 | 仓储接口 + 平台实现 | 移动端评估 SQLite，Web 评估 IndexedDB |
| 音频 | 优先评估 Expo 官方音频模块 | 验证两端播放、本地音频和中断 |
| 后端 | 首版本地模式不依赖后端 | 同步与 AI 阶段再加入 |

依赖版本在初始化时按兼容关系锁定。原生能力通过开发构建验证，不仅依赖 Expo Go。具体存储和音频选型在最小验证后确定。

### 架构边界

1. 领域层：判题、进度计算、复习调度，不依赖页面。
2. 内容层：课程包、版本校验、语言特性、资源索引。
3. 数据层：读写、迁移、备份与恢复。
4. 平台层：音频、文件、下载、通知。
5. 界面层：页面、组件、交互。

文件、音频和存储通过适配器处理；不能假设原生插件可以直接运行在浏览器中。

### 建议目录

- app/：页面路由入口。
- src/features/：课程、练习、复习、进度、设置。
- src/domain/：数据模型、判题、复习规则。
- src/data/：仓储、持久化、迁移、备份。
- src/platform/：平台接口与实现。
- src/components/：共用组件。
- content/：语言配置、课程、资源清单。
- assets/：随包音频、图片、字体。
- docs/：产品计划、内容规范、技术决策。

## 6. 核心数据

| 实体 | 用途 |
| --- | --- |
| LanguageProfile | 语言标签、文字方向、文字系统、转写及语言特性 |
| Course | 用户母语、目标语言、级别、单元、版本 |
| Lesson | 学习目标、步骤、知识点与练习引用 |
| LearningItem | 可复习的词汇、短句、规则 |
| Exercise | 题型、题干、答案规则、解释、知识点引用 |
| MediaAsset | 音频路径、语言、口音、资源版本与授权 |
| Attempt | 作答、正确性、时间、题目版本 |
| LessonProgress | 当前步骤、完成情况、最近位置 |
| ReviewState | 掌握状态、上次复习、下次到期时间 |
| UserPreferences | 界面语言、学习与音频偏好 |

使用稳定 ID 和结构版本。课程更新不能静默清空进度，不兼容变化通过迁移或明确提示处理。

填空按语言配置大小写、标点和可接受答案，不统一去除空格或变音符号。自由表达不采用简单字符串相等判分。

## 7. 离线与可靠性

- Android 首批示范课程和必要音频随包提供。
- Web 缓存应用及课程资源，首次成功加载并缓存后支持离线；音频也需要缓存。
- 下载未完成不能标记为可离线，资源失败可重试。
- 作答、进度、复习状态写入持久化存储，重启可恢复。
- 浏览器存储可能被清理或回收，本地保存不等于云备份。
- 导出文件带版本，导入前校验，并明确覆盖或合并规则。
- 初期不做云同步，为后续同步保留稳定标识与变更信息。

## 8. 分阶段实施

### 阶段 0：课程样本与内容规范

- [ ] 确认首版母语、目标语言、用户人群。
- [ ] 列出 10 节示范课学习目标。
- [ ] 定义课程、知识点、题目、语言配置与资源格式。
- [ ] 制作 1 节完整样本，校对例句、答案、音频授权。

验收：样本覆盖完整单课流程，内容可独立于界面审核。

### 阶段 1：项目与平台基础

- [ ] 初始化 Expo + TypeScript 与目录、路由。
- [ ] 建立基础组件、排版和文字显示规则。
- [ ] 打通 Android 开发构建与 Web 构建。
- [ ] 验证存储、资源加载和音频播放。

验收：Android 真机与浏览器均可播放音频、保存并恢复学习记录。

### 阶段 2：单课学习闭环

- [ ] 实现首页、课程目录与课时页面。
- [ ] 展示词汇、例句、讲解和音频。
- [ ] 实现选择、填空、排序、听音选择。
- [ ] 保存学习位置，展示解释和课后结果。

验收：两端完成同一节课，重启可恢复位置；排序提供按钮或键盘操作。

### 阶段 3：复习与进度

- [ ] 实现可解释的间隔复习规则，记录算法版本。
- [ ] 将已学知识点和错题关联到复习状态。
- [ ] 实现每日复习与基础统计。
- [ ] 处理到期时间、时区、重复提交和中途退出。

验收：复习安排可重现，重复提交不重复累计，重启后到期状态一致。

### 阶段 4：离线、备份与内容

- [ ] 完成 Android 离线资源与 Web 缓存。
- [ ] 完成数据导出、校验与恢复。
- [ ] 补齐并校对 10 节示范课程。
- [ ] 处理资源失败、空状态、存储异常。

验收：两端通过预期离线场景，恢复备份后进度与复习安排一致。

### 阶段 5：首版交付

- [ ] 验证 Android 真机、桌面及移动浏览器关键流程。
- [ ] 检查音频、输入、字体、键盘和可访问性。
- [ ] 生成 Android 测试安装包和 Web 构建产物。
- [ ] 编写运行、构建、课程维护和备份说明。
- [ ] 记录限制，确定正式部署与分发方式。

验收：无需开发工具即可安装 Android 测试包，Web 构建可部署并完成核心学习流程。

## 9. 验证重点

- 判题：可接受答案、语言差异、空答案、重复提交。
- 复习：到期边界、时区、连续答错、状态恢复。
- 数据：课程升级、数据库迁移、异常导入。
- 音频：重复播放、中断、断网、资源缺失。
- 平台：返回、键盘遮挡、Web 刷新和路由直达。
- 文字：非拉丁文字、组合字符、长文本和 RTL 样例。

测试聚焦业务规则与用户流程，不为低风险展示组件机械补齐测试。

## 10. 升级边界

### 多语言

选择第二种文字或语法特征不同的语言验证模型，再扩展覆盖。只开放已有合格课程的语言。

### 云同步

另行确定账号、鉴权、隐私、冲突处理和后端数据库。服务端 API 密钥不写入客户端。

### AI 与语音

录音、对话、表达反馈、发音评测独立设计接口。按语言维护能力清单，不支持的维度不打分。发音评测必须使用原始音频，不能仅从文字推断。

### iOS

核心流程稳定后，单独安排 Mac/Xcode 构建、插件兼容、真机和分发验证。

## 11. 下一步

从阶段 0 开始：确认课程目标和内容格式，制作 1 节样本。随后初始化工程，先验证两端音频与持久化，再展开页面开发。
